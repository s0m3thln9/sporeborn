# Порядок работы с Git

## Ветки и слияния

- `dev` — ветка интеграции. Создавай отдельную ветку от актуальной `dev` для каждой задачи, включая документацию и настройки. После проверок сливай ветку задачи в `dev`.
- `prod` — ветка выпуска. Сливай в неё `dev` только по прямому указанию пользователя. Готовое слияние можно предложить, указав, какие изменения войдут в выпуск.
- Используй английские имена в нижнем регистре с дефисами. Примеры `feature/mushroom-pickup`, `fix/duplicate-sale`, `docs/project-workflow`, `chore/unity-settings`, `refactor/box-state` и `test/save-restore`.
- В репозитории без истории первый коммит становится базой для `dev`. Создавай `prod` только при явном запросе на создание ветки или выпуск.
- Перед ответвлением проверь рабочее дерево и актуальность `dev`. Перед слиянием проверь diff и затронутый сценарий. Используй fast-forward, когда возможно. При расхождении сохраняй обе истории обычным merge с явным однострочным заголовком Conventional Commits. Разрешая конфликт, сохраняй смысл обеих сторон и проверяй итог.

## Коммиты

- Самостоятельно создавай коммиты для проверенных изменений. Один коммит охватывает одно связное изменение. Добавляй файлы явно и проверяй `git diff --cached` и `git diff --cached --check`. Пользовательские изменения включай только в пределах согласованного объёма.
- Формат заголовка — `type(scope): summary`. Используй короткое английское описание действия без точки. Примеры `fix(sales): prevent duplicate payouts` и `docs(workflow): define git rules`.
- Оставляй коммиту только заголовок. Запрещены тело, футеры и указание соавторства. Запрет на указание соавторства действует также для PR и сопроводительных материалов.

## Синхронизация и история

- Самостоятельно выполняй `fetch`, `pull`, обычный `push` и другие обратимые операции в рамках задачи. Проверяй имя удалённого репозитория и целевую ветку перед отправкой. При первом push указывай upstream.
- Для общих веток используй `git pull --ff-only`. При расхождении проверь обе стороны через `fetch` и сравнение коммитов. Исправления общей истории делай новым коммитом или через `git revert`.
- Перед необратимыми операциями запрашивай подтверждение. Сюда входят force-push, переписывание опубликованной истории, принудительное удаление неслитых веток и удаление пользовательских незакоммиченных или неотслеживаемых файлов.

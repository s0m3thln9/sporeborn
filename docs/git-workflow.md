# Порядок работы с Git

## Ветки и слияния

- `dev` — ветка интеграции. Создавай отдельную ветку от актуальной `origin/dev` для каждой задачи, включая документацию и настройки. После проверок открой PR из ветки задачи в `dev`.
- `prod` — ветка выпуска. Переход `dev` → `prod` выполняй отдельным PR и только по прямому указанию пользователя. В описании укажи вошедшие изменения и выполненные проверки.
- Сливай ветки только через PR на GitHub. Локальный `git merge` и прямой push в целевую ветку для интеграции запрещены. `git pull --ff-only` допустим для обновления локальной копии той же ветки.
- Используй английские имена веток в нижнем регистре с дефисами. Примеры — `feature/mushroom-pickup`, `fix/duplicate-sale`, `docs/project-workflow`.
- В репозитории без истории первый коммит становится базой для `dev`. Создавай `prod` только при явном запросе на создание ветки или выпуск.

## Pull request

- **Заголовок** описывает итог всей ветки на английском. Первое слово с заглавной буквы, без тире и префикса Conventional Commits. Пример — `Enforce pull request merges`.
- **Описание** — выжимка из коммитов. Укажи, что изменилось и зачем, затем перечисли выполненные проверки. Если применимая проверка не запускалась, укажи это. Не добавляй соавторов.
- Перед слиянием проверь целевую ветку, итоговый diff и статус применимых проверок. Если при слиянии создаётся отдельный коммит, дай ему однострочный заголовок Conventional Commits без тела и соавторов.

## Коммиты

- Самостоятельно создавай коммиты для проверенных изменений. Один коммит охватывает одно связное изменение. Добавляй файлы явно и проверяй `git diff --cached` и `git diff --cached --check`. Пользовательские изменения включай только в пределах согласованного объёма.
- Формат заголовка — `type(scope): summary`. Используй короткое английское описание действия без точки. Примеры — `fix(sales): prevent duplicate payouts` и `docs(workflow): define git rules`.
- Оставляй коммиту только заголовок. Запрещены тело, футеры и указание соавторства.

## Синхронизация и история

- Самостоятельно выполняй `fetch`, `pull`, push ветки задачи и другие обратимые операции в рамках задачи. Проверяй имя удалённого репозитория и целевую ветку перед отправкой. При первом push указывай upstream.
- При расхождении локальной и удалённой общей ветки сохрани локальную историю и сравни её с удалённой. Для отдельной задачи начни от удалённой ветки без переноса несвязанных коммитов. Исправления общей истории проводи через PR с новым коммитом или `git revert`.
- Перед необратимыми операциями запрашивай подтверждение. Сюда входят force-push, переписывание опубликованной истории, принудительное удаление неслитых веток и удаление пользовательских незакоммиченных или неотслеживаемых файлов.
